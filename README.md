# Визуализатор зависимостей Java-пакетов Maven

Практическая работа № 2. Конфигурационное управление. РТУ МИРЭА, ИКБО-62-25, вариант 11.

Программа принимает YAML, читает XML-файлы POM по HTTP и строит ориентированный граф.
Стрелка A → B означает, что для работы A требуется B. Исходный текст Mermaid и PNG сохраняются рядом.
Для получения зависимостей используются стандартные библиотеки Python urllib и ElementTree.
PyYAML читает конфигурацию, Graphviz рисует PNG по тем же узлам и рёбрам, что и Mermaid.

## Запуск на macOS

Клонируйте репозиторий и перейдите в его корневой каталог. Нужны Python 3.9+ и программа dot из Graphviz.
При установленном Homebrew команда для Graphviz — `brew install graphviz`.

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
sh run.sh examples/test.yaml
open build/diamond.png
python3 -m unittest discover -s tests -v
```

Сборка не требуется. На Windows после установки зависимостей можно вызвать
`python src/main.py examples/test.yaml`. Пример с Maven Central — `sh run.sh examples/live.yaml`.

## Параметры

| Поле | Значение и проверка |
|---|---|
| package | Координата groupId:artifactId или имя из заглавных латинских букв для тестового графа. |
| version | Фиксированная версия строкой, например "4.13.2". Для буквенного графа версия условная. |
| repository | Базовый URL HTTP(S) либо путь к YAML-файлу со списками смежности. |
| test_mode | Логическое true для буквенного графа, false для чтения POM по HTTP. |
| output | Имя PNG. В том же каталоге создаётся одноимённый файл .mmd. |
| max_depth | Целое число ≥ 0. При 0 виден только корень, при 1 видны прямые зависимости. |

Относительные пути отсчитываются от YAML-файла. Тестовый репозиторий перечисляет все узлы, включая листья.
Пример — `A: [B, C]`. Для листа пишут `B: []`. Неизвестные поля и ссылки на отсутствующие узлы вызывают ошибку.
Тест конфигурации по очереди подставляет ошибочное значение в каждое из шести полей.

## Пять этапов

| Ветка Git | Функциональность версии | Демонстрация |
|---|---|---|
| stage-1 | Проверка YAML, вывод ключей и значений | run.sh examples/live.yaml |
| stage-2 | HTTP-загрузка POM и вывод прямых зависимостей | run.sh examples/live.yaml |
| stage-3 | Рекурсивный BFS и вывод списка смежности | run.sh examples/test.yaml |
| stage-4 | Вывод топологического порядка либо конкретного цикла | run.sh examples/cycle.yaml |
| stage-5 | Сохранение Mermaid и PNG | run.sh examples/test.yaml |

Чтобы воспроизвести промежуточный этап, можно создать отдельную рабочую копию.
Команды ниже выполняются из корня проекта с активированной виртуальной средой.

```sh
git log --oneline --decorate
git worktree add --detach ../variant11-order origin/stage-4
sh ../variant11-order/run.sh ../variant11-order/examples/test.yaml
sh ../variant11-order/run.sh ../variant11-order/examples/leaf.yaml
sh ../variant11-order/run.sh ../variant11-order/examples/cycle.yaml
```

Последняя команда завершается с ошибкой и указывает цикл. Для показа этапов 1–3 используется соответствующая ветка origin/stage-N.
Для этапа 2 можно взять конфигурацию examples/junit.yaml из итоговой версии и запустить локальный HTTP-сервер ниже.

## Алгоритм и проверка

BFS начинает с корня на уровне 0. Все узлы текущего уровня добавляют своих соседей в следующий фронт.
После обработки уровня функция вызывает себя для следующего. Уже обнаруженный узел сохраняет все входящие
рёбра, но добавляется в очередь один раз. Узлы на предельной глубине отображаются без запроса их POM.
Рекурсивная реализация рассчитана на графы, глубина которых меньше предела рекурсии Python.

| Корень и глубина | Полученный граф | Порядок загрузки на этапе 4 |
|---|---|---|
| A, 8 | A → B, A → C, B → D, C → D | D, B, C, A. Узел D встречается один раз. |
| A, 1 | A → B, A → C | B, C, A, только в пределах видимой части графа. |
| A, 0 | A | A |
| X, 8 | X → Y → Z → X | Полный порядок невозможен. Этап 5 сохраняет граф с обратной стрелкой. |
| L, 8 | L без рёбер | L |

## Три примера Maven

В examples/poms находятся сокращённые учебные POM с зависимостями выбранных версий.
При запуске сервера файлы читаются по HTTP в обычном Maven-режиме. Запустите в одном терминале:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory examples/poms
```

Во втором терминале, из того же каталога с активированной виртуальной средой:

```sh
sh run.sh examples/junit.yaml
sh run.sh examples/hamcrest-library.yaml
sh run.sh examples/hamcrest-core.yaml
```

Команды создают изображения и Mermaid-файлы в build. Для проверки с полными опубликованными POM
укажите в этих конфигурациях repository из examples/live.yaml. Требуется доступ к Maven Central.

| Корень | Вычисленный граф runtime | Порядок этапа 4 |
|---|---|---|
| junit:junit:4.13.2 | junit → hamcrest-core:1.3 | hamcrest-core, junit |
| org.hamcrest:hamcrest-library:1.3 | hamcrest-library → hamcrest-core:1.3 | hamcrest-core, hamcrest-library |
| org.hamcrest:hamcrest-core:1.3 | Один узел | hamcrest-core |

### Сопоставление с Maven

Опубликованное Maven-дерево JUnit 4.13.2 показывает hamcrest-core как compile, а hamcrest-library как test.
После фильтрации по runtime остаётся одно ребро, как в первом графе.
В опубликованном дереве Maven Core 3.8.9 ветвь hamcrest-library 1.3 содержит hamcrest-core 1.3.
У hamcrest-core в этой ветви нет потомков. Эти связи совпадают со вторым и третьим графами.
Scope test у ветви в общем дереве отражает её использование самим проектом Maven Core.

Команда ниже скачивает артефакты настоящим Apache Maven. Для каждого корня создаётся пустой кэш,
параллелизм загрузки ограничен. Из журнала берутся завершённые передачи POM и JAR выбранных пакетов.
В comparison.txt можно сопоставить порядок JAR с топологическим порядком этапа 4.
Топологический порядок диктует готовность зависимостей к использованию. Maven сначала читает дескрипторы,
затем получает архивы по расписанию своего резолвера. Поэтому потребитель может скачаться раньше зависимости.
Общий POM или JAR обычно повторно не передаётся при заполненном кэше.

Для этапа 5 скрипт сравнивает узлы и рёбра программы с поддеревом Maven dependency:tree в JSON,
исключая проверочный проект edu.practice:comparison. На несовпадении проверка завершается ошибкой.
Оба PNG и Mermaid-файл записываются вместе с эталонным DOT и журналом в build/reference/<artifact>/.
Для запуска требуются Maven, Java, Graphviz и доступ к Maven Central.

```sh
sh examples/reference/compare.sh
```

Опубликованные отчёты:

- https://junit.org/junit4/dependencies.html
- https://maven.apache.org/components/ref/3.8.9/maven-core/dependencies.html

### Область поддержки

Этап 2 выводит прямые объявления всех областей видимости, включая test и optional.
Для транзитивного графа используются обязательные зависимости compile/runtime с фиксированными версиями.
Поддерживаются простые свойства, родительские POM, версии из dependencyManagement и импортируемых BOM.
Профили, exclusions, системные свойства, диапазоны версий, специальные SNAPSHOT-метаданные,
классификаторы и полное разрешение конфликтов Maven не реализованы.
Если разные пути ведут к двум версиям, они отображаются как отдельные узлы.
В конфигурациях со сложным наследованием результат следует сверять с effective-pom.

## Устройство программы

| Модуль | Функции |
|---|---|
| config.py | load читает YAML, проверяет поля и разрешает относительные пути. |
| maven.py | document читает XML, model кэширует данные, read_model собирает свойства и версии. |
| maven.py | expand раскрывает свойства, coordinate определяет версию, children возвращает прямые зависимости. |
| graph.py | test_repository проверяет списки смежности, bfs обходит уровни графа. |
| order.py | load_order строит порядок с учётом всех рёбер и сообщает о цикле. |
| render.py | render создаёт текст Mermaid и изображение Graphviz. |
| main.py | run выбирает источник и выполняет операцию соответствующего этапа. |
